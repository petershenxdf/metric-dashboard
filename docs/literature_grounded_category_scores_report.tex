\begin{abstract}
This report defines a deterministic evidence specification for prioritizing
records in an interactive active-learning dashboard. The system combines
semi-supervised clustering and outlier detection from \ssdbcodi, shallow
decision-tree rules used only as explanations, and a large language model used
only to translate fixed evidence into ordinary language. Earlier designs used
weighted mixtures of boundary uncertainty, representativeness, label coverage,
local density, and rule evidence. Although such mixtures can rank records, their
meaning depends on arbitrary project-level weights and is difficult to explain
to users.

The revised design replaces those mixtures with five atomic evidence
categories: \emph{Cluster Assignment Conflict}, \emph{Weak Group
Reachability}, \emph{Local Sparsity}, \emph{Known-Outlier Similarity}, and
\emph{Rule Disagreement}. Each category answers one labeling question and uses
one score with a single interpretation. Three scores are direct transformations
of the reachability, local-density, and similarity scores introduced by
\ssdbcodi. Neighbor disagreement adapts a published instance-hardness measure
to reachability neighborhoods, while rule disagreement is a point-level
surrogate-fidelity measure defined by this project. Every record receives a
deterministic score record, including an explicit availability status when the
required labels, groups, or rules do not yet exist. The published aggregate
\ssdbcodi outlier score remains model context; rule-cutoff distance remains an
auxiliary Rule Panel view. Neither becomes an evidence category. This separation
makes the selection process reproducible, auditable, and concise enough for a
visual interface intended for non-expert users.
\end{abstract}

\noindent\textbf{Keywords:} active learning, semi-supervised clustering,
evidence score, outlier detection, rule-based explanation, visual analytics,
human-in-the-loop machine learning

\section{Motivation}

Active learning aims to obtain useful supervision while minimizing labeling
effort \cite{settles2009survey,tong2001svm}. In an interactive clustering and
outlier-analysis system, however, a record can be useful for several
fundamentally different reasons. It may lie among records assigned to different
groups, be weakly connected to all currently known groups, occupy a sparse
neighborhood, resemble a confirmed outlier, sit close to a rule cutoff, or
contradict a simple rule. These observations do not have the same semantics and
should not be hidden inside one weighted total.

The previous category design combined several such observations using fixed
percentages. For example, a boundary score mixed cluster-border distance,
neighbor composition, representativeness, and rule proximity. This created
three problems:

\begin{enumerate}[leftmargin=*,itemsep=0.25em]
  \item A displayed score no longer answered one precise question.
  \item The recommendation order depended on weights that were neither learned
  nor established as optimal by the cited literature.
  \item A user could not tell which observation actually caused a record to be
  recommended.
\end{enumerate}

The revised principle is therefore:

\begin{quote}
\textbf{One category, one labeling question, one score, and one direction of
interpretation.}
\end{quote}

Eligibility rules, labeling history, batch construction, and interface wording
remain important, but they are kept outside the mathematical definition of the
category score.

\subsection{Responsibility boundaries}

The scoring design preserves the system's existing ownership boundaries:

\begin{itemize}[leftmargin=*,itemsep=0.25em]
  \item \ssdbcodi owns cluster assignments, outlier status, and its published
  detector scores \cite{deng2022ssdbcodi}.
  \item Decision trees are read-only surrogate explanations. They describe
  current \ssdbcodi outputs but do not perform clustering or outlier detection.
  \item Deterministic code computes scores, availability, ranks, and recommended
  record identifiers.
  \item DeepSeek V4 Pro may rewrite supplied facts into concise user-facing
  language, but it cannot calculate a score, change a category, add a reason,
  or alter the recommendation order.
\end{itemize}

\section{Notation and Shared Computation}

Let a dataset contain $N$ records. After deterministic preprocessing, record
$q$ is represented by a model-space vector $\mathbf{z}_q\in\R^d$. Numeric
features are imputed and scaled; categorical features are encoded according to
the dataset adapter. Original values and a feature-transformation map are
retained so that the interface can use the original field names and units.

Let
\begin{equation}
  d(p,q)=\lVert\mathbf{z}_p-\mathbf{z}_q\rVert_2
  \label{eq:euclidean}
\end{equation}
denote model-space Euclidean distance. Let $cDist(q)$ be the distance from $q$
to its $MinPts$-th nearest neighbor. Following \ssdbcodi, the pairwise
reachability distance is
\begin{equation}
  rDist(p,q)=\max\{cDist(p),cDist(q),d(p,q)\}.
  \label{eq:reachability-distance}
\end{equation}

Let $c(q)$ denote the current normal-cluster assignment of $q$. Outlier status
is stored separately and is not treated as an ordinary semantic cluster. Let
$D_N$ be the set of labeled normal references and $D_O$ the set of
human-confirmed outliers. When the current session has no human labels, a
provider may use bootstrap references, but their provenance must be displayed
as \emph{bootstrap} rather than \emph{human-confirmed}.

All geometric scores use the complete model feature space. Two-dimensional
scatterplot coordinates are excluded from score computation because projection
can distort high-dimensional proximity.

\subsection{Score range and availability}

Every point has a score record for every required score key. An available
record contains a numeric score in $[0,1]$; an unavailable record contains a
null score and one of the following statuses:

\begin{description}[leftmargin=3.2cm,style=nextline,itemsep=0.2em]
  \item[\status{available}] The required groups, references, or rules exist and
  the score has its stated meaning.
  \item[\status{insufficient\_reference}] The formula requires a type of human
  reference that has not yet been supplied.
  \item[\status{insufficient\_support}] The required rule or neighborhood exists
  but contains too few records for a defensible estimate.
  \item[\status{not\_applicable}] The current analysis has no meaningful object
  for the category, such as a second cluster or a non-trivial rule.
\end{description}

Unavailable scores use \status{raw\_score=null}; they must never be encoded as
zero, because zero is a valid observation when the evidence is available. For
available scores, the display score is
\begin{equation}
  S^{display}(q)=\operatorname{round}(100S(q)).
  \label{eq:display-score}
\end{equation}
It is a category-specific index, not a probability or confidence estimate.
Scores may be compared among records within the same category, dataset version,
preprocessing version, and active-learning round. They must not be interpreted
as commensurate across categories or datasets.

\subsection{Cluster Assignment Conflict: Reachability-kDN Score}

\paragraph{Labeling question.}
Do nearby, similar records support this record's current group assignment?

Let $D_C$ be the records currently assigned to normal clusters. For a clustered
record $q$, let
\begin{equation}
  k_q=\min(MinPts,|D_C|-1)
\end{equation}
and let $\mathcal{N}^{r}_{k_q}(q)$ contain the $k_q$ nearest records to $q$ in
$D_C\setminus\{q\}$ under $rDist$. The score is
\begin{equation}
  \boxed{
  S_{conflict}(q)=
  \frac{1}{k_q}
  \sum_{p\in\mathcal{N}^{r}_{k_q}(q)}
  \indicator[c(p)\neq c(q)].}
  \label{eq:conflict}
\end{equation}

A score of zero means that all selected neighbors have the same current group
assignment as $q$. A score of one means that every selected neighbor is assigned
elsewhere. Intermediate values directly state the share of nearby records that
disagree with the current assignment.

Equation~\eqref{eq:conflict} has the same counting form as the
$k$-Disagreeing Neighbors instance-hardness measure, which quantifies local
class overlap \cite{smith2014instance}. The adaptation replaces ground-truth
classes with current \ssdbcodi assignments and Euclidean neighbors with
reachability neighbors. It is therefore not the original published kDN score.
Active clustering provides the broader motivation for spending supervision on
uncertain cluster structure \cite{xiong2017active}. No representativeness term,
rule term, or affected-region weight is added.

A value near one does not necessarily mean that $q$ lies geometrically between
two groups. It may instead be embedded inside a different assigned group. The
category is therefore named \emph{Cluster Assignment Conflict}, not
\emph{Boundary} or \emph{Between Groups}.

The score has status \status{not\_applicable} when fewer than two normal groups
exist, when $q$ is currently treated as an outlier, or when no neighbor can be
formed.

\subsection{Weak Group Reachability: Reachability Gap Score}

\paragraph{Labeling question.}
Is this record difficult to connect to every currently known normal group?

For a normal reference $s\in D_N$, let $E_{max}(q,s)$ denote the largest
reachability edge along the density-expansion path from $q$ to $s$. Define
\begin{equation}
  p_{min}=\arg\min_{s\in D_N}E_{max}(q,s).
  \label{eq:closest-normal-reference}
\end{equation}
The \ssdbcodi paper defines
\begin{equation}
  rScore(q)=e^{-E_{max}(q,p_{min})}.
  \label{eq:rscore}
\end{equation}
The evidence score reverses its direction:
\begin{equation}
  \boxed{S_{far}(q)=1-rScore(q).}
  \label{eq:far}
\end{equation}

This score is directly grounded in the Reachability Assumption of \ssdbcodi:
outliers and records outside known normal structure tend to be less
density-reachable from labeled normal records \cite{deng2022ssdbcodi}. A high
score asks whether the record belongs to an existing type, represents an
uncovered type, or should be considered unusual. It does not assert any of
those outcomes automatically.

When $D_N$ is empty, the score has status
\status{insufficient\_reference}. If bootstrap seeds are used, the score may be
computed, but its source must be marked as bootstrap evidence.

\paragraph{Implementation consistency note.}
The paper's Equations~\eqref{eq:closest-normal-reference}--\eqref{eq:rscore} use
pathwise $E_{max}$. The current NumPy provider in \systemname computes
$\exp(-\min_{s\in D_N}rDist(q,s))$, using the minimum direct pairwise
reachability distance. This is a deterministic approximation, not the exact
paper definition. Any experiment or interface using the current provider must
identify its semantics as \status{direct\_rdist\_approximation}; it must not
claim \status{paper\_exact} until the expansion-path computation is aligned.

\subsection{Local Sparsity: Local Sparsity Score}

\paragraph{Labeling question.}
Does this record occupy a locally sparse part of the data?

Let $nearest_i(q)$ be the $i$-th nearest neighbor of $q$ under $rDist$. The
\ssdbcodi local-distance quantity is
\begin{equation}
  LD(q)=\frac{1}{MinPts}
  \sum_{i=1}^{MinPts}rDist(nearest_i(q),q),
  \label{eq:local-distance}
\end{equation}
and the paper defines
\begin{equation}
  lScore(q)=e^{-LD(q)}.
  \label{eq:lscore}
\end{equation}
The category score is
\begin{equation}
  \boxed{S_{sparse}(q)=1-lScore(q).}
  \label{eq:sparse}
\end{equation}

A high value has one precise interpretation: the reachability distances to the
local neighbors are large. This is consistent with density-based anomaly
research, in which unusual records often occur in locally sparse regions
\cite{breunig2000lof,deng2022ssdbcodi}. The score does not incorporate distance
to a normal seed, similarity to known outliers, data-quality warnings, or rule
evidence. Those are separate observations.

The score is available whenever a valid reachability neighborhood can be
constructed. Sparse does not mean incorrect: a high-scoring record may be a
valid rare case, a coherent but small type, a true outlier, or a data problem.
The user's label determines which interpretation is appropriate.

\subsection{Known-Outlier Similarity: Known-Outlier Similarity Score}

\paragraph{Labeling question.}
Does this record resemble an outlier that a person has already confirmed?

For an unlabeled candidate $q$ and $D_O\neq\varnothing$, define
\begin{equation}
  o_{min}=\arg\min_{o\in D_O}d(q,o).
  \label{eq:nearest-outlier}
\end{equation}
The \ssdbcodi similarity score is used without additional terms:
\begin{equation}
  \boxed{
  S_{known\text{-}outlier}(q)=simScore(q)=e^{-d(q,o_{min})}.}
  \label{eq:known-outlier}
\end{equation}

This score implements the \ssdbcodi Similarity Assumption: some outliers occur
in related patterns rather than as isolated singletons
\cite{deng2022ssdbcodi}. Human feedback is essential because proximity to a
known outlier does not prove that the new record has the same real-world
meaning. Active anomaly discovery similarly uses analyst feedback to adapt the
system's concept of a relevant anomaly \cite{das2016aad}.

If $D_O$ is empty, the raw score is null and the status is
\status{insufficient\_reference}. The interface must say that no confirmed
outlier reference exists; it must not describe the records as dissimilar.
When scores are materialized for an already confirmed outlier, $q$ itself is
removed from the reference set before Equation~\eqref{eq:nearest-outlier} is
evaluated. If no other confirmed outlier remains, the score is null. This
self-exclusion prevents a labeled record from receiving the trivial score one
merely by matching itself.

\paragraph{Implementation migration note.}
The current detector implementation returns a numeric zero when no labeled
outlier exists and returns one for a labeled outlier's self-match. Those values
remain valid inside the existing $tScore$ implementation. The atomic evidence
adapter must, however, emit null for a missing reference and exclude self as
specified above. This change belongs at the evidence-contract boundary and must
not silently alter historical detector runs.

\subsection{Rule Disagreement: Leaf Target Disagreement Score}

\paragraph{Labeling question.}
Does the record contradict the simple description of its current analysis
region?

For a non-trivial surrogate tree $t$, let $\ell_t(q)$ denote the terminal leaf
reached by $q$, and let $y_t(q)$ denote the source analysis target for $q$:
cluster assignment for a cluster surrogate or outlier status for an anomaly
surrogate. Let $n_{\ell}$ be the number of records in leaf $\ell$, and let
$n_{\ell,y}$ be the number with target $y$. Define the disagreement witnessed
by tree $t$ as
\begin{equation}
  \boxed{
  S_{disagreement,t}(q)=
  1-\frac{n_{\ell_t(q),y_t(q)}}{n_{\ell_t(q)}}
  }.
  \label{eq:tree-mismatch}
\end{equation}

The category never takes a maximum across rule families. It exposes two
separate target-kind views, \emph{Cluster Rule Disagreement} and
\emph{Outlier Rule Disagreement}. A high score means that most records sharing
this leaf's simple description have a different source-analysis target. The
record may be a genuine exception, or the surrogate rule may be too simple.
Human labeling helps distinguish these explanations.

The estimate is available only when
$n_{\ell_t(q)}\geq m_{\mathrm{rule}}$, with
$m_{\mathrm{rule}}=5$ as the initial minimum-support policy. Smaller leaves
return a null score with status \status{insufficient\_support}. The value five
is a declared policy choice, not a literature-derived optimum, and must be
included in the sensitivity analysis.
This audit gate is independent of the tree's training-time
\status{min\_samples\_leaf}. A smaller leaf may remain visible in the Rule Panel
for descriptive completeness while its disagreement score remains unavailable.

Rule-based visual analytics can make anomaly and group descriptions accessible
for interactive review \cite{deng2021rissad}. Surrogate-model research defines
fidelity as agreement between the surrogate and its target model
\cite{chatzimparmpas2024deforestvis}. Equation~\eqref{eq:tree-mismatch} is a
point-level adaptation of that construct; it is not claimed as an established
query-selection objective. The surrogate remains explanation-only and cannot
automatically relabel, merge, split, or reassign a record. If no non-trivial
surrogate exists, the status is \status{not\_applicable}.

\section{Auxiliary Rule-Cutoff View}

Distance to a numeric surrogate-rule cutoff remains useful for navigating the
Rule Panel, but it is not one of the five evidence categories. For tree $t$,
let $\mathcal{P}_t(q)$ be the split nodes traversed by $q$. For an eligible
numeric split $b$ with model feature $f_b$ and transformed threshold $\tau_b$,
define the standardized margin
\begin{equation}
  \delta(q,b)=|z_{qf_b}-\tau_b|.
  \label{eq:rule-margin}
\end{equation}
The auxiliary view sorts records by increasing
$\min_{t,b\in\mathcal{P}_t(q)}\delta(q,b)$. It does not apply an exponential
mapping or present the margin as a calibrated score.

Threshold-focused active learning establishes that observations around an
unknown functional threshold can be valuable, but published methods generally
select queries using entropy, misclassification risk, or variance rather than
distance to a post-hoc surrogate split \cite{bryan2005threshold}. RISSAD
supports the value of interactive descriptive rules, not this acquisition
formula \cite{deng2021rissad}. The auxiliary status therefore remains
\status{project\_hypothesis} until an independent experiment demonstrates
labeling utility. Categorical one-hot splits are excluded because distance to a
threshold such as $0.5$ has no semantic notion of closeness.

\section{Evidence Provenance and Claim Levels}

The report separates provenance of the numerical construct from evidence that
the construct is an effective query policy. The following labels are normative:

\begin{description}[leftmargin=3.6cm,style=nextline,itemsep=0.25em]
  \item[\status{published\_formula}] The score is copied from a cited method or
  is a declared monotone reversal used only to align the direction ``higher
  means more evidence.''
  \item[\status{literature\_adaptation}] A published construct motivates the
  score, but the neighborhood, target, or unit of analysis has been changed.
  \item[\status{project\_hypothesis}] The numerical relationship is proposed by
  this project and has not been established as an effective acquisition policy.
\end{description}

Table~\ref{tab:provenance} records both kinds of claim. In particular, a
published detector formula does not imply that querying its highest-scoring
record will produce the greatest improvement in the next active-learning
round. That second claim requires independent evaluation.

\section{Role of the Published Aggregate Outlier Score}

The \ssdbcodi paper combines three detector signals as
\begin{equation}
  tScore(q)=
  \alpha(1-rScore(q))+
  \beta(1-lScore(q))+
  (1-\alpha-\beta)simScore(q),
  \label{eq:tscore}
\end{equation}
where $\alpha,\beta\in[0,1]$ and $\alpha+\beta\leq1$
\cite{deng2022ssdbcodi}. This is the published aggregate used by the detector;
it is not an arbitrary dashboard formula.

Nevertheless, $tScore$ is not an evidence category in the revised design.
The dashboard may show it in technical details to explain current \ssdbcodi
outlier status, but it must not use it to rank a category. The acquisition
interface exposes the three constituent questions separately:

\begin{itemize}[leftmargin=*,itemsep=0.2em]
  \item Is the record far from every known normal group?
  \item Is its local neighborhood sparse?
  \item Does it resemble a confirmed outlier?
\end{itemize}

This choice preserves the original detector while allowing the user to know
which kind of evidence motivates a labeling request.

\section{Why the Previous Composite Categories Are Removed}

Several previous category names described useful analytical hypotheses but did
not correspond to one measurable property.

\paragraph{Coverage Gaps.}
A meaningful coverage gap requires both distance from existing human labels and
evidence that the region represents more than one isolated record. Those are
two different constructs. The revised dashboard may describe such a hypothesis
when both observations are available, but it does not manufacture a weighted
Coverage Gap Score.

\paragraph{Emerging Groups.}
A possible new group must be separated from existing groups, internally
coherent, and semantically supported by human labels. No single pointwise
number establishes all three. The system may surface a transparent conjunction
of atomic facts, but it must not state that a high scalar score proves a new
cluster.

\paragraph{Label Priority.}
Scores from different categories have different meanings and are not calibrated
as a common utility. A cross-category weighted meta-ranker would recreate the
same interpretability problem. The interface therefore presents categories as
separate labeling questions rather than claiming that, for example, a sparse
score of $80$ is more important than a rule-disagreement score of $75$.

\paragraph{Rule Checks.}
Proximity to a rule cutoff and disagreement with a rule are distinct. The first
supports navigation around a displayed threshold, while the second measures
whether the rule describes its region consistently. Only disagreement remains
an evidence category. Cutoff proximity is an auxiliary Rule Panel ordering and
must not be shown as a calibrated score. Cluster-target and outlier-target rule
disagreement are separate views rather than subtypes hidden behind a maximum.

\section{Normative Score Contract}

Each computed score is represented by the following conceptual record:

\begin{verbatim}
AtomicEvidenceScore
  point_id
  category_id
  target_kind            # null | cluster | outlier
  score_id
  raw_score              # deterministic value in [0, 1] | null
  display_score          # round(100 * raw_score) | null
  availability           # available | insufficient_reference |
                         # insufficient_support | not_applicable
  evidence_level         # published_formula | literature_adaptation |
                         # project_hypothesis
  formula_source_ids
  adaptation_note        # required for non-exact reuse
  category_rank          # integer | null
  score_policy_version
  dataset_version_id
  preprocessing_version
  analysis_run_id
  label_revision
  source_fact_ids
  source_rule_id         # optional
  source_reference_ids   # optional
  support_count          # optional
  minimum_support        # optional
  technical_details
\end{verbatim}

The following invariants apply:

\begin{enumerate}[leftmargin=*,itemsep=0.25em]
  \item Every dataset record has one score record for every required score key.
  Rule Disagreement uses separate \status{cluster} and \status{outlier} keys;
  these values are never collapsed by a maximum.
  \item The same immutable dataset, preprocessing, analysis, labels, parameters,
  and score-policy version produce the same value and rank.
  \item A category rank is computed only among records with
  \status{available} status.
  \item Ties are resolved by stable point identifier.
  \item An unavailable score has a null raw value, display value, and rank. It
  cannot enter recommendation sorting.
  \item Every score retains sufficient provenance to reconstruct its value and
  distinguish a published formula from a project adaptation.
  \item Ground-truth columns reserved for offline evaluation are never used.
\end{enumerate}

\section{Scoring Versus Recommendation Policy}

The atomic evidence score answers why a point is relevant to one category. It
does not guarantee that labeling the point will improve the next analysis, and
it does not encode whether the point is currently eligible for recommendation.
The selection pipeline is explicitly separated:

\begin{equation}
  \text{materialize evidence for all points}
  \rightarrow
  \text{filter eligibility}
  \rightarrow
  \text{sort within category}
  \rightarrow
  \text{construct the batch}.
\end{equation}

Eligibility may exclude a point that already has an active label, belongs to an
obsolete round, lacks the required score status, or is still under a repeat-
recommendation cooldown. A labeled point may re-enter only with a recorded
reason such as a changed cluster assignment, changed outlier status, or new
rule conflict.

History penalties, affected-region size, and batch diversity must not be added
to the displayed category score. If batch construction omits a higher-scoring
eligible point to avoid an exact duplicate or to satisfy a declared batch
constraint, the plan records that reason separately. This guarantees that the
score shown to the user is the score that established category relevance. The
empirical evaluation, rather than the score definition, determines whether that
relevance translates into labeling utility.

\section{User-Facing Representation and LLM Contract}

The default visual representation for a recommended record is compact:

\begin{quote}
\textbf{record\_114 \hfill Cluster Assignment Conflict: 67/100}

Several of this record's closest neighbors are currently placed in another group.
Labeling it can help check whether its present group assignment makes sense.

\emph{Compared with:} record\_031, record\_087
\end{quote}

The card contains one score bar, one plain-language observation, one sentence
explaining why the observation matters, and optional comparison records. Exact
distances, thresholds, neighbors, rules, and transformations remain in a
collapsed \emph{Technical details} section.

DeepSeek V4 Pro receives only the fixed category, score direction, deterministic
facts, comparison targets, allowed labels, and relevant rule text. It may:

\begin{itemize}[leftmargin=*,itemsep=0.2em]
  \item replace technical terms with ordinary language;
  \item explain what records or original fields the user should compare; and
  \item describe at most two conditional outcomes of the user's label.
\end{itemize}

It may not change a score, availability status, category, point order, source
record, source rule, or recommended identifier. It may not infer similarity
from scatterplot distance, recommend an automatic merge or split, or present a
score as probability. Schema failure replaces only the affected wording with
deterministic text; it never changes the recommendation plan.

\section{Evaluation Plan}

The revised framework eliminates cross-construct weight tuning, but it does not
make query utility self-evident. Evaluation must test three claims separately:

\begin{description}[leftmargin=2.2cm,style=nextline,itemsep=0.2em]
  \item[Construct] The score changes monotonically with the single property
  named by its category.
  \item[Utility] Querying high-scoring eligible records improves the relevant
  active-learning outcome more quickly than a baseline policy.
  \item[Usability] A person can understand why the record was surfaced and can
  act on the evidence without mistaking the score for confidence.
\end{description}

Passing a construct test is necessary but not sufficient for claiming labeling
utility.

\subsection{Contract, determinism, and leakage tests}

For each supported dataset adapter and active-learning round, verify that:

\begin{itemize}[leftmargin=*,itemsep=0.2em]
  \item every point has one record for each of the four non-rule categories and
  one record for each supported Rule Disagreement target kind;
  \item every available raw value is finite and lies in $[0,1]$;
  \item repeated computation produces identical values and ranks;
  \item unavailable records contain null raw values, display values, and ranks,
  together with the correct non-available status;
  \item rule leaves below $m_{\mathrm{rule}}$ return
  \status{insufficient\_support};
  \item score provenance references only the current round ancestry; and
  \item ground-truth evaluation columns, future-round labels, and scatterplot
  coordinates never enter score computation.
\end{itemize}

\subsection{Construct and monotonicity tests}

Synthetic datasets should isolate each intended property:

\begin{itemize}[leftmargin=*,itemsep=0.2em]
  \item replacing same-group neighbors with other-group neighbors must increase
  $S_{conflict}$;
  \item increasing $E_{max}$ to every normal reference must increase $S_{far}$;
  \item increasing mean local reachability distance must increase $S_{sparse}$;
  \item moving a point toward a confirmed outlier must increase
  $S_{known\text{-}outlier}$;
  \item reducing the share of matching targets in a rule leaf must increase
  $S_{disagreement,t}$ for that target kind; and
  \item reducing a numeric point's standardized distance to a traversed rule
  threshold must move it earlier in the auxiliary cutoff ordering, without
  creating a category score.
\end{itemize}

Each test changes one construct while holding the others fixed where possible.
This directly tests semantic meaning rather than the behavior of an arbitrary
weighted total.

\subsection{Labeling-utility evaluation}

Use wine only as one reproducible fixture. The study must also include numeric,
mixed-type, missing-value, CSV, JSON, and MAT datasets, plus synthetic datasets
whose boundary, density, outlier, and rule-exception structure is controlled.
Ground truth acts only as a simulated oracle after candidate selection.

For repeated initial-label seeds and matched label budgets, compare:

\begin{itemize}[leftmargin=*,itemsep=0.2em]
  \item uniform random sampling;
  \item each of the five atomic within-category ranking policies;
  \item the published \ssdbcodi $tScore$ ranking for anomaly-focused tasks;
  \item the previous weighted composite policy; and
  \item a model-based active-clustering uncertainty baseline when its query
  type is compatible with the session \cite{xiong2017active}.
\end{itemize}

Measurements should include:

\begin{itemize}[leftmargin=*,itemsep=0.2em]
  \item area under the learning curve for ARI or NMI over label budget;
  \item area under the learning curve for anomaly average precision or ROC AUC;
  \item labels required to reach a predeclared task-quality threshold;
  \item category-specific outcomes, such as corrected local assignment
  conflicts, discovered confirmed outliers, and reduced surrogate disagreement;
  \item recommendation stability for identical session states; and
  \item overlap among categories, reported as a finding rather than suppressed
  by hidden diversity weights.
\end{itemize}

Report paired differences across the same dataset, seed, and budget with 95\%
bootstrap confidence intervals and a predeclared paired test. A category should
be described as an effective query policy only when it improves its relevant
outcome consistently; a published component formula alone is not sufficient.

\subsection{Sensitivity and ablation analysis}

The following choices require explicit analysis rather than silent defaults:

\begin{itemize}[leftmargin=*,itemsep=0.2em]
  \item $MinPts$ and the resulting reachability neighborhood size;
  \item exact pathwise $E_{max}$ versus the current direct-$rDist$
  approximation;
  \item human-confirmed versus bootstrap normal references;
  \item the rule support gate $m_{\mathrm{rule}}$, including at least values
  3, 5, and 10 where dataset size permits;
  \item surrogate depth and minimum leaf size; and
  \item numeric scaling, categorical encoding, and missing-value treatment.
\end{itemize}

Cluster Rule Disagreement and Outlier Rule Disagreement are evaluated
separately. An ablation must not restore a maximum across target kinds, because
that would obscure which analysis result the human label is meant to audit.

\subsection{Human-centered evaluation}

A user study should test whether participants can correctly answer three
questions after viewing a recommendation:

\begin{enumerate}[leftmargin=*,itemsep=0.2em]
  \item Why was this record recommended?
  \item What should it be compared with?
  \item What would different labels tell the system?
\end{enumerate}

Compare the atomic score card with the previous multi-question evidence matrix
using completion time, explanation accuracy, perceived workload, and trust
calibration. The objective is not to maximize stated trust, but to help users
distinguish strong evidence, missing evidence, and model limitations.

\section{Limitations}

The five scores are intentionally narrow. They do not estimate the total future
improvement caused by a label, and they do not provide a universal ordering
across different labeling questions. Distance-based values depend on the
preprocessing and feature weighting chosen for the dataset. High-dimensional
or high-cardinality categorical data may require additional validation of the
model-space metric.

Cluster Assignment Conflict uses current model assignments where published kDN
uses known classes. It can therefore expose model inconsistency, but it can also
inherit a globally poor clustering. Neighbor disagreement may indicate a
boundary, an assignment error, or a sparse point between groups. Weak Group
Reachability and Local Sparsity are also statistically related because both use
reachability distance; displaying them separately improves semantic clarity but
does not make them independent.

Known-Outlier Similarity is unavailable before a user confirms an outlier and
is only as reliable as that reference. Rule Disagreement inherits the
limitations of the shallow surrogate, the support gate, and in-sample leaf
counts. Out-of-fold fidelity should be investigated before treating its
magnitude as robust. Neither the disagreement score nor the auxiliary cutoff
view is a direct property of the source clustering model.

Finally, the current direct-$rDist$ approximation to the paper's pathwise
$E_{max}$ requires explicit provenance and empirical comparison before the
system can claim exact SSDBCODI reachability semantics.
Until the utility experiments are complete, all five scores should be described
as deterministic evidence for candidate prioritization, not as proven optimal
acquisition functions.

\section{Conclusion}

This report replaces weighted acquisition mixtures with five atomic evidence
scores. Each score has one formula, one labeling question, one direction of
interpretation, and reconstructable evidence. Three expose the original
\ssdbcodi reachability, local-density, and known-outlier similarity mechanisms;
one adapts neighborhood disagreement to current cluster assignments; and one
audits target disagreement inside the explanatory rule layer. The published
aggregate outlier score remains part of \ssdbcodi but not part of category
ranking, while rule-cutoff proximity remains an auxiliary navigation view.

This architecture makes the deterministic recommendation contract easier to
study and the visual explanation easier to understand. It also gives the LLM a
better-defined role: translating established facts into clear language without
participating in scoring or selection. The proposed evaluation then determines
which evidence scores also function as effective active-learning query policies.
